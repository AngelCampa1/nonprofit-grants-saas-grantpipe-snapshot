## How to Use This Scorecard

This scorecard is designed for mid-sized nonprofits ($500K-$10M annual budget) evaluating CRMs for donor management and fundraising operations. It is not a feature checklist - it is a scoring framework that forces you to weigh what matters to your organization against what each vendor actually delivers.

**Before you start evaluating:**

1. Assemble a small evaluation team (2-4 people): development director, a daily CRM user, someone from finance, and optionally the ED.
2. Agree on weight adjustments (explained below) before looking at any vendor.
3. Schedule live demos with at least 3 vendors. Prepare the same scenario for each: "Show us how you handle [your most common workflow]."
4. Have each evaluator score independently after the demo, then compare and discuss.

**Scoring scale:** For each item within a category, rate the vendor 1-5:

- 5: Excellent - does this better than we need
- 4: Good - meets our needs fully
- 3: Adequate - works but has friction or limitations
- 2: Poor - technically possible but painful
- 1: Missing or broken - does not do this in any practical way

## Category 1: Donor Management (Weight: 25%)

This is the core function. If the CRM does not handle donor records well, nothing else matters.

| Item                                                                                | Vendor A | Vendor B | Vendor C |
| ----------------------------------------------------------------------------------- | -------- | -------- | -------- |
| Donor record completeness (contact info, giving history, interactions, notes)       |          |          |          |
| Gift entry speed and accuracy (can a coordinator enter 20 gifts in 15 minutes?)     |          |          |          |
| Duplicate detection and merge                                                       |          |          |          |
| Household/organization linking                                                      |          |          |          |
| Custom fields (can you track what your org needs without workarounds?)              |          |          |          |
| Communication logging (emails, calls, meetings attached to donor record)            |          |          |          |
| Donor search and filtering (find donors by gift amount, date range, campaign, etc.) |          |          |          |
| Batch gift entry (events, mail appeals)                                             |          |          |          |
| Recurring gift management (setup, tracking, failed payment alerts)                  |          |          |          |
| Moves management / major donor pipeline tracking                                    |          |          |          |

**Category score:** Sum of ratings / 50, multiplied by 25 = weighted score

**What to watch for in demos:** Ask the vendor to find all donors who gave $250+ last year but have not given this year. If this requires a consultant or a support ticket, the tool is too complex for your team.

## Category 2: Grant Tracking (Weight: 15%)

Not all nonprofit CRMs handle grants well. Some bolt it on. Some ignore it entirely.

| Item                                                           | Vendor A | Vendor B | Vendor C |
| -------------------------------------------------------------- | -------- | -------- | -------- |
| Grant record with funder, amount, period, and status           |          |          |          |
| Deadline and reporting schedule tracking                       |          |          |          |
| Automatic reminders for upcoming deadlines                     |          |          |          |
| Grant budget vs. actual expense tracking                       |          |          |          |
| Document storage linked to grant records                       |          |          |          |
| Grant pipeline (prospects, submitted, pending, active, closed) |          |          |          |
| Renewal tracking and history                                   |          |          |          |

**Category score:** Sum of ratings / 35, multiplied by 15 = weighted score

**What to watch for:** If the vendor says "you can track grants in a custom module" or "our customers use a workaround," the CRM does not really support grants. A workaround is not a feature.

## Category 3: Reporting and Analytics (Weight: 20%)

Reports are how you make decisions and communicate results to the board. Weak reporting means you will end up in spreadsheets anyway.

| Item                                                                                | Vendor A | Vendor B | Vendor C |
| ----------------------------------------------------------------------------------- | -------- | -------- | -------- |
| Pre-built fundraising reports (LYBUNT, SYBUNT, donor retention, giving by campaign) |          |          |          |
| Custom report builder (can you build reports without SQL or consultant help?)       |          |          |          |
| Dashboard with real-time fundraising totals                                         |          |          |          |
| Export to CSV or Excel                                                              |          |          |          |
| Grant reporting: can you pull data formatted for funder requirements?               |          |          |          |
| Donor retention rate calculation (built in, not manual)                             |          |          |          |
| Board-ready report generation (formatted, not raw data)                             |          |          |          |
| Year-over-year comparison                                                           |          |          |          |
| Campaign performance tracking                                                       |          |          |          |

**Category score:** Sum of ratings / 45, multiplied by 20 = weighted score

**The export test:** During the demo, ask the vendor to export a donor list with giving history to Excel. If export is limited (e.g., only 500 records at a time, or key fields are not exportable), you will hit this wall regularly. Your data should be fully portable.

## Category 4: Integrations (Weight: 10%)

A CRM that does not connect to your accounting system creates double-entry. A CRM that does not connect to your email platform creates blind spots.

| Item                                                           | Vendor A | Vendor B | Vendor C |
| -------------------------------------------------------------- | -------- | -------- | -------- |
| QuickBooks or Xero integration (two-way, not just export)      |          |          |          |
| Email platform integration (Mailchimp, Constant Contact, etc.) |          |          |          |
| Payment processor integration (Stripe, PayPal, etc.)           |          |          |          |
| Website donation form that syncs to CRM automatically          |          |          |          |
| Wealth screening integration (DonorSearch, iWave, etc.)        |          |          |          |
| API availability for custom integrations                       |          |          |          |

**Category score:** Sum of ratings / 30, multiplied by 10 = weighted score

**The accounting integration is non-negotiable.** If gifts entered in the CRM do not flow to your accounting system automatically, someone is doing double data entry. At 2,000+ gifts per year, that is a significant time cost and an error source.

## Category 5: Implementation Cost (Weight: 10%)

The sticker price is not the real price. Implementation, data migration, and training can double the first-year cost.

| Item                                                                                        | Vendor A | Vendor B | Vendor C |
| ------------------------------------------------------------------------------------------- | -------- | -------- | -------- |
| Data migration: is it included, and who does the work?                                      |          |          |          |
| Training: hours included, format (live vs. recorded), additional cost                       |          |          |          |
| Implementation timeline: weeks from signing to live                                         |          |          |          |
| Consultant requirement: can you set it up without paying a third-party consultant?          |          |          |          |
| Configuration: can your team customize fields, forms, and workflows without developer help? |          |          |          |

**Category score:** Sum of ratings / 25, multiplied by 10 = weighted score

**Hidden cost questions to ask every vendor:**

- What is the total cost for the first year including implementation?
- Do we need to hire a certified consultant for data migration?
- What happens if we need more training after go-live?
- Are there additional fees for custom report creation?

## Category 6: Ongoing Cost (Weight: 10%)

Monthly or annual fees are the most visible cost, but pricing models vary wildly across nonprofit CRMs.

| Item                                                                | Vendor A | Vendor B | Vendor C |
| ------------------------------------------------------------------- | -------- | -------- | -------- |
| Monthly/annual subscription cost for your expected user count       |          |          |          |
| Pricing model clarity (per user? per record? flat rate? tiered?)    |          |          |          |
| Cost predictability (will price increase as your donor base grows?) |          |          |          |
| Nonprofit discount available and applied                            |          |          |          |
| Cost of additional modules you will need (grants, events, etc.)     |          |          |          |
| Payment processing fees (if using built-in donation forms)          |          |          |          |

**Category score:** Sum of ratings / 30, multiplied by 10 = weighted score

**The 3-year cost calculation:** Ask each vendor to quote their total cost for Year 1, Year 2, and Year 3 assuming your donor base grows 10% per year. Per-record pricing models can become very expensive as you grow. A CRM that costs $200/month today might cost $500/month in 3 years on a per-record model.

## Category 7: Learning Curve (Weight: 5%)

The fanciest CRM in the world is worthless if your team will not use it.

| Item                                                                                | Vendor A | Vendor B | Vendor C |
| ----------------------------------------------------------------------------------- | -------- | -------- | -------- |
| Time for a new user to perform basic tasks (gift entry, donor lookup, run a report) |          |          |          |
| Interface clarity: can a non-technical user navigate without training?              |          |          |          |
| Help documentation quality (searchable, up to date, with screenshots)               |          |          |          |
| Live support availability (chat, phone, email response time)                        |          |          |          |

**Category score:** Sum of ratings / 20, multiplied by 5 = weighted score

**The intern test:** If you brought in a college intern with no CRM experience, could they enter gifts and pull a basic report within their first day? If not, the learning curve is too steep for an organization where staff turnover in development roles is common.

## Category 8: Consultant Dependency (Weight: 5%)

Some CRMs are designed to be self-service. Others are designed to sell you consulting hours. Know which you are getting.

| Item                                                                                | Vendor A | Vendor B | Vendor C |
| ----------------------------------------------------------------------------------- | -------- | -------- | -------- |
| Can you add custom fields without a consultant?                                     |          |          |          |
| Can you modify donation forms without a consultant?                                 |          |          |          |
| Can you build new reports without a consultant?                                     |          |          |          |
| Can you add new users and set permissions without a consultant?                     |          |          |          |
| Is there a certified consultant ecosystem? (This is a warning sign, not a feature.) |          |          |          |

**Category score:** Sum of ratings / 25, multiplied by 5 = weighted score

**The self-sufficiency test:** Ask the vendor: "After implementation, what will we need your consulting team for?" If the answer is anything more than "you won't," dig deeper. A CRM that requires paid consulting for routine changes is a CRM that costs more than the sticker price suggests, every year, forever.

## Final Scoring Summary

| Category                 | Weight   | Vendor A | Vendor B | Vendor C |
| ------------------------ | -------- | -------- | -------- | -------- |
| Donor Management         | 25%      |          |          |          |
| Grant Tracking           | 15%      |          |          |          |
| Reporting & Analytics    | 20%      |          |          |          |
| Integrations             | 10%      |          |          |          |
| Implementation Cost      | 10%      |          |          |          |
| Ongoing Cost             | 10%      |          |          |          |
| Learning Curve           | 5%       |          |          |          |
| Consultant Dependency    | 5%       |          |          |          |
| **Total Weighted Score** | **100%** |          |          |          |

**Adjusting weights for your organization:** The weights above reflect a typical mid-sized nonprofit where donor management and reporting drive the most daily value. If your organization is grant-heavy, increase Grant Tracking weight and decrease another. If you have zero technical staff, increase Learning Curve and Consultant Dependency weights.

The vendor with the highest weighted score is your strongest candidate - but do not skip the reference check. Ask the vendor for 2-3 references at organizations similar to yours in size and mission. Ask those references the one question that matters most: "If you were choosing again today, would you pick the same CRM?"
