Shared costs are normal in nonprofit programs. One software subscription may support two grants. One program manager may supervise several funded activities. One training room may be used by more than one program. The issue is not that costs are shared. The issue is whether the split is fair, allowed, and supported.

For federal awards, 2 CFR 200.405 covers allocable costs. The plain idea is that a cost should be assigned to the award in proportion to the benefit received. That principle is useful even when the funder is a city, foundation, or donor.

This guide gives a practical way to document shared costs. It is not legal or accounting advice.

## Start with the cost

Do not start with the grant budget. Start with the actual cost. Pull the invoice, payroll detail, contract, receipt, or journal entry. Confirm the cost exists, belongs to the period, and has support.

Then ask which grants or programs benefited. If only one grant benefited, do not split it. If several benefited, list them.

Examples of shared costs include:

- Program manager payroll
- Shared case management software
- Rent for a program space
- Outreach supplies used across grants
- Training costs for staff serving several awards
- Insurance or occupancy costs assigned through a cost plan

## Check allowability first

An allocation cannot fix an unallowable cost. Before splitting the cost, check whether the cost is allowed by each grant. Review the award terms, approved budget, period of performance, and any prior approval rules.

For federal grants, 2 CFR 200.403 is a starting point for allowability. A cost should be necessary, reasonable, allocable, consistent, and supported. Some costs may need extra review.

If one grant does not allow the cost, leave that grant out of the allocation even if the program benefited.

## Pick a basis that matches benefit

The allocation basis should fit the cost. A good basis can be explained in one sentence.

Examples:

- Staff hours for shared payroll
- Square footage for shared space
- Number of participants served
- Number of licenses used
- Direct cost base under an approved policy
- Actual units used

Avoid splits chosen only because the budget has room. Budget room does not prove benefit.

The basis should be consistent. If the team changes the basis, write down why. A change may be valid when program volume changes, a grant ends, or the cost pattern changes.

## Build the calculation

Create a simple allocation worksheet. It should show the total cost, grants included, basis used, units by grant, percentage by grant, dollar split, budget line, and reviewer approval.

For example, if a shared software cost is split by active users, list users by program for the month. If Grant A had 12 users and Grant B had 8 users, the split is 60 percent and 40 percent. Attach the user count report.

If payroll is involved, use the [grant funded payroll allocation guide](/resources/guides/grant-funded-payroll-allocation-guide). Payroll often needs stronger support because staffing changes can shift the benefit pattern.

## Compare to budget and deadlines

After calculating the split, compare each charge to the grant budget. Check whether the cost is inside the grant period. Also check whether the grant report or reimbursement deadline is near.

If the allocation would push a budget line over its limit, do not hide the issue. Review whether a budget revision, reclass, or funder approval is needed.

Shared costs can also affect cash timing. If a reimbursement grant pays later, unrestricted cash may carry the cost for a while.

## Save audit evidence

The file should include the source cost, allocation method, calculation, budget check, approval, and ledger entry. If the method comes from a cost allocation plan, attach or cite the plan.

Do not rely on a spreadsheet with no source. The spreadsheet explains the split. It does not prove the invoice, payroll, or program volume.

GrantPipe can help keep shared cost support tied to grant compliance records, restricted funds, deadlines, and reporting files. The system should make the review easier, not replace it.

## Review monthly

Shared allocations should not run on autopilot. Review them during month-end close. Ask whether the cost still exists, the grants still benefit, the basis still fits, and the budget still allows the charge.

Program staff should help confirm the benefit pattern. Finance should approve the calculation. Grants staff should check funder terms and reporting effects.

## Common mistakes

Common mistakes include splitting costs by available budget, using old percentages after work changes, charging ended grants, forgetting prior approval, and saving the calculation without the invoice.

Another mistake is mixing direct allocation and indirect cost recovery without review. If a cost is treated as indirect under a cost plan, do not also charge it directly unless the policy and award terms support that treatment.

Shared cost allocation should be boring and explainable. A reviewer should be able to open the file, see the cost, understand who benefited, follow the math, and find the approval.
