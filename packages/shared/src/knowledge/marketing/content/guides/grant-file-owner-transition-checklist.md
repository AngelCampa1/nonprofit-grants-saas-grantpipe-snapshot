Grant files can fall apart during staff changes. The outgoing owner may know where the funder email lives, which report is tricky, which reimbursement is delayed, and which folder has the signed award. If that knowledge does not move, the next owner starts with a puzzle.

A grant file owner transition checklist protects deadlines, documents, cash, compliance, and funder relationships. Use it when staff resign, go on leave, change roles, or hand a grant from development to operations after award.

This checklist is not about blame. It is about continuity. The next owner should know what is due, what is missing, what is risky, and where the proof lives.

## Start with the active deadline list

Deadlines are the first risk. Before reviewing old files, list every active and upcoming date.

Include:

- report due dates
- reimbursement dates
- renewal dates
- closeout dates
- budget revision dates
- funder meeting dates
- board approval dates
- internal review dates
- data lock dates

For each date, list owner, status, support needed, and where the related file lives.

If the transition happens fast, this deadline list is the most important handoff.

## Transfer award terms

The new owner needs the signed award and any later amendments. They also need a plain summary of the terms.

Summarize award amount, grant period, payment method, restrictions, reporting dates, match, budget categories, prior approval rules, closeout requirements, record retention, and funder contact.

Do not rely on the new owner to read the full agreement on day one. They should read it, but the transition should point to the issues that matter now.

Use the [grant award acceptance checklist](/resources/guides/grant-award-acceptance-checklist) to confirm the award setup is complete.

## Review report status

Reports need a separate handoff. For each active report, show due date, report owner, finance support needed, program data needed, draft status, submission method, and reviewer.

Name any report that is late, blocked, or tied to payment.

If the funder has portal access rules, document who has access and who can submit. Do not share passwords in the transition packet. Follow the organization's access policy.

Use the [grant reporting calendar template](/resources/guides/grant-reporting-calendar-template) to keep report dates visible.

## Review finance status

Finance items can create hidden risk. The new owner should know what money has been received, what is receivable, what costs have been charged, and whether any restricted balance needs attention.

Review:

- grant code or fund code
- approved budget
- spending pace
- reimbursement requests
- receivable aging
- match support
- restricted fund balance
- budget revisions
- costs needing review

This guide is not accounting advice. It is a transition prompt. Finance should confirm the numbers and the treatment.

## Review document completeness

Use a file index. Do not hand over a folder full of names and hope the new owner finds the right support.

The file should include award documents, amendments, approved budget, reports, report receipts, invoices, reimbursement support, match support, approvals, funder emails, monitoring notes, closeout proof, and board approvals when needed.

Use the [grant compliance file index template guide](/resources/guides/grant-compliance-file-index-template-guide) and [grant documentation checklist](/resources/guides/grant-documentation-checklist-audit-ready) for this step.

If a file is missing, name it. A known gap is better than a hidden gap.

## Transfer funder context

The next owner needs more than documents. They need context.

Record funder contact names, preferred contact method, portal links, standing meetings, current questions, open promises, renewal signals, and sensitive issues.

Do not add gossip. Add facts that help the next owner communicate well.

Example: "Funder asked for updated participant counts on June 20. Program expects final count by July 3. Send through the portal, not email."

## Transfer risks and decisions

List open risks in plain language.

Examples:

- "May underspend staffing line because hiring was delayed."
- "Reimbursement request is 35 days old."
- "Closeout needs final equipment inventory."
- "Program data for Q2 is missing from one site."
- "Renewal decision depends on board approval of match."

For each risk, name owner, next date, and decision needed.

If a risk belongs on the board register, link it to the [nonprofit board grant risk register guide](/resources/guides/nonprofit-board-grant-risk-register-guide).

## Update access and ownership

Transitions are also access events. Update system owner fields, shared drive permissions, funder portal users, task owners, calendar invites, and email groups.

Remove access that is no longer needed. Add access before the outgoing owner leaves when possible.

GrantPipe can help by showing grant owners, tasks, notes, documents, and deadlines in the grant record. A transition is easier when ownership is visible instead of hidden in personal files.

## Hold a transition meeting

Use a 30 to 60 minute meeting for active grants. The outgoing owner, incoming owner, manager, and finance contact should attend when possible.

Agenda:

1. Active deadlines.
2. Award terms.
3. Reports.
4. Finance status.
5. Missing documents.
6. Funder context.
7. Open risks.
8. Access changes.
9. Next seven days.

End with a written owner change and next action list. The handoff is not complete until the new owner can find the files and explain the next deadline.
