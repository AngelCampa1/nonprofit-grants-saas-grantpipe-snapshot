# Nonprofit audit request list response guide

An audit request list can look like a long set of chores. It works better when finance treats it as a control log. Each request needs an owner, a due date, a source file, and a clean answer. That simple structure helps the team avoid duplicate work and gives the auditor less reason to ask the same question again.

This guide is not legal or accounting advice. Use it to organize work before your auditor reviews the records. Ask your CPA how to handle technical judgments.

## Build one master tracker

Start with the request list exactly as the auditor sent it. Do not rewrite the request in softer language. Keep the item number, request text, due date, and format. Add columns for owner, status, file link, review notes, submitted date, and auditor follow-up.

Use one tracker for the whole audit. Separate spreadsheets for finance, payroll, grants, and programs make it hard to see what is late. A single tracker also helps the executive director and board treasurer see risk early.

Useful statuses are simple:

- Not started
- Waiting on source record
- In staff review
- Ready for finance review
- Submitted
- Auditor follow-up needed
- Closed

The status should show the real state. "Submitted" does not mean closed. It only means the file was sent. Keep the item open until the auditor accepts it or no longer needs it.

## Assign the person who can answer

Each request needs one owner. The owner may need help, but one person should be accountable. A payroll register belongs with payroll or finance. A grant agreement may belong with the grant owner. Board minutes may belong with the executive assistant or secretary.

Avoid group names like "program team." They make follow-up slow. Use a role or name, then list support roles in the notes.

For grant compliance items, include the grant owner and finance reviewer. Program staff may know what happened. Finance must still confirm that the amount, date, and coding tie to the accounting record.

## Clarify before preparing a file

Auditor requests can be broad. "Provide support for grant revenue" may mean award letters, cash receipts, receivable schedules, or all three. Ask before staff prepare a folder that does not answer the test.

Good questions are short:

- What period should this cover?
- Do you need detail or summary?
- Should this tie to the trial balance?
- Do you want Excel, PDF, or both?
- Is this for all grants or a sample?

Clear scope saves time. It also reduces the risk of sending extra data the auditor did not request.

## Name files so they can stand alone

Each file name should explain what the file is. "Bank rec March operating account 2026.pdf" is better than "scan004.pdf." For grant files, include the grant name, period, and evidence type.

Use a folder structure that mirrors the request list. If the auditor asks for item 3.2, the file should sit in a folder named 3.2. This makes the audit trail easier to follow.

For schedules, keep the working format. Auditors often need Excel for ledgers, trial balances, and reconciliations. Use PDF for signed policies, board minutes, grant agreements, and bank statements.

## Review before submission

Do not make the auditor the first reviewer. A finance reviewer should check each item before it is submitted.

Review for five things:

- The file answers the request
- The date range is correct
- The totals tie to the ledger or schedule
- Sensitive data is limited to what was requested
- The file name and folder match the tracker

If a file does not tie out, write a short explanation before submission. A known timing difference is easier to handle than a silent mismatch.

## Handle samples with care

Auditor sample requests need fast, exact answers. If the auditor selects five expenses, provide the invoice, approval, payment proof, grant coding, and any required procurement support for each one.

Do not send a full vendor folder when the auditor asked for one invoice. Send the requested evidence and a short index. If the sample relates to federal grants, include allowability support, approval, and the grant period check.

GrantPipe helps teams keep donor CRM records, grant compliance files, restricted funds, deadlines, audit evidence, and reporting in one system. That can make sample response work easier because the evidence is tied to the grant and the deadline that created it.

## Track follow-up as new work

Follow-up requests are not side notes. Add each one to the tracker. Link it back to the original request, assign an owner, and give it a due date.

This matters because follow-up can grow fast during fieldwork. If it stays in email, items get missed. If it lives in the tracker, leadership can see what is blocking closeout.

Use short notes. "Auditor asked for signed March review" is enough. "Need more info" is not.

## Keep final evidence after the audit

When fieldwork ends, save the final tracker and submitted files. Keep them with the audit report, management letter, and any corrective action plan. For federal awards, 2 CFR 200 record retention rules may apply. Your auditor or counsel can tell you what period applies to a specific file.

Next year, use the closed tracker as the starting point. Remove items that no longer apply. Add new grants, restricted funds, bank accounts, systems, and reporting changes.

The best response process is boring. Every item has an owner. Every file has a name. Every amount ties back. Every open question is visible. That is how a long request list becomes a managed audit workflow.
