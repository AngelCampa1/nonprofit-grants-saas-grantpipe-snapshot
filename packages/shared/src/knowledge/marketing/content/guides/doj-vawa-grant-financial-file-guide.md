# DOJ VAWA grant financial file guide

VAWA grant files have two jobs that can conflict. Finance has to prove every cost and match entry. The program has to protect survivor privacy. A good file does both. It gives DOJ, OVW, auditors, and board reviewers enough financial support without placing survivor personally identifying information in the finance file.

Start with the [DOJ OVC and VAWA reporting guide](/resources/guides/doj-ovc-vawa-reporting-requirements) for the reporting frame. This guide focuses on the financial file that supports those reports.

## Keep survivor data out of the finance folder

VAWA confidentiality rules protect personally identifying information. That includes obvious items like names and addresses. It can also include details that could identify or locate a survivor.

Do not store client names in reimbursement packets, match schedules, budget notes, or report backup. Use de-identified service counts, payroll records, vendor invoices, and internal references. The case management system can hold client-level records under stricter access rules. The grant finance file should not become a second case file.

## Create a file map

Make one file map for each VAWA award. Include these sections:

- Notice of award and award conditions
- Approved budget and budget changes
- Grant ledger by period
- Payroll and time support
- Vendor invoices and approvals
- Match register and match support
- SF-425 support
- PMT report backup with aggregate data only
- Prior approvals and correspondence
- Closeout records

Each section should answer one review question. Was the cost allowed? Was it in the approved budget? Was it in the project period? Was it documented? Was privacy protected?

## Document payroll without overexposing services

Personnel costs are often the largest VAWA cost. They also carry risk because staff may split time across programs. Time records should show the staff member, period, grant activity, hours, approval, and allocation. They should not list survivor names.

If a staff member worked on hotline coverage, legal advocacy, or shelter services, the time record can name the activity. It does not need the client's identity. Tie the payroll allocation to the [time and effort guide](/resources/guides/time-and-effort-certification-federal-grants) so finance has a consistent method.

## Build a match register

Many VAWA awards require non-federal match, but the exact rule depends on the program and award. Use the notice of award and DOJ guidance as the source. The match register should list source, type, amount, date, valuation method, support, and whether the match has been reported.

Cash match needs proof of the source, receipt, and eligible use. In-kind match needs proof that the service or item was provided and valued in a reasonable way. Volunteer time should use a current log, not a memory-based estimate after the period ends.

If match support relates to direct services, keep it de-identified. A donated counseling hour can be supported by date, service type, provider, rate, and hours. It should not name the person served.

## Tie reports to the ledger

The SF-425 should tie to the grant ledger, draw records, and match register. Before filing, compare federal expenditures, cash received, cash disbursed, and match claimed. If those numbers do not agree, fix the source record before filing.

PMT reports should tie to aggregate program data, not client records in the finance file. Keep the report export and a de-identified summary showing how counts were built. If a reviewer needs more detail, use the privacy process approved by program leadership.

## Keep prior approvals visible

Budget changes, scope changes, and some cost changes may require prior approval. Keep each request, approval, and related budget table in the file. If a cost moved between budget categories, the file should show why the move was allowed.

Do not bury approvals in email. Save them with the financial records they affect. During audit or monitoring, the reviewer should not have to search one person's inbox.

## Review vendor and contractor costs

Vendor invoices should show the service, period, amount, approval, and grant tie. If the vendor had access to survivor information, keep the confidentiality and data handling terms with the contract. The financial file can show the contract exists and was approved without copying sensitive client data into the packet.

Use the [allowable costs guide](/resources/guides/allowable-costs-federal-grants) for the basic cost test. Then add the VAWA privacy test before storing support.

## Close cleanly

At closeout, confirm the final ledger, final SF-425, final PMT report, match register, and draw records agree. Remove duplicate or unnecessary copies of sensitive material. Keep required financial records under federal retention rules and any longer award terms.
