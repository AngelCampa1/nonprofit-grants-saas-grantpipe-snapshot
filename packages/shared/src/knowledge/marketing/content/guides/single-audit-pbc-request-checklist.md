# Single audit PBC request checklist

A single audit asks for more than normal financial audit support. It also asks whether the nonprofit followed federal award rules for major programs. The PBC checklist should prove both money and compliance. That means the team needs grant files, controls, reports, approvals, and samples ready before fieldwork starts.

This guide is a planning tool. It does not replace your auditor's request list or professional advice.

## Start with the SEFA tie-out

The SEFA is the first file to prepare because it drives the audit scope. It should list federal award spending for the fiscal year. It should include direct federal awards and federal awards passed through states, counties, cities, schools, or other nonprofits.

Prepare a tie-out that shows how each SEFA line maps to the general ledger. Include account codes, grant codes, fund codes, and any adjustments. If one ledger code includes federal and nonfederal activity, show how the federal share was split.

Keep these files together:

- Draft SEFA
- Final SEFA
- Ledger detail by award
- Award list with Assistance Listing numbers
- Pass-through award letters
- Notes for adjustments and exclusions

If the SEFA is wrong, the rest of the audit gets harder. Missing a federal program can affect major program selection and reporting.

## Build a folder for each federal program

Each federal program needs a file that can stand alone. The auditor should be able to see what the award was, what period it covered, what rules applied, what was spent, and what reports were submitted.

Use the same folder sections for every program:

- Award documents
- Budget and amendments
- General ledger detail
- Financial reports
- Program reports
- Payroll and time records
- Procurement records
- Subrecipient records
- Monitoring and review notes

If the award came through a pass-through entity, include the pass-through agreement and correspondence. That agreement often names special terms, report deadlines, and identification numbers.

## Document internal controls

Auditors test controls for major programs. They may ask how staff approve costs, review reports, monitor subrecipients, or check eligibility. A policy alone is not enough. The file should show the control happened.

For each major process, keep the written policy, the workflow owner, the reviewer, and evidence of review. For example, a federal financial report file should include the report, the ledger support, and the review signoff before submission.

Good control evidence is dated and traceable. A verbal explanation is useful, but it does not replace a record.

## Prepare expense sample support

The auditor may select expense samples after fieldwork starts. Build the file structure now so the response is fast.

For each sampled expense, provide:

- Invoice or receipt
- Purchase approval
- Payment proof
- Ledger detail
- Grant or fund code
- Budget line
- Allowability note if needed
- Procurement support if required

For payroll samples, include the payroll register, approved pay rate, time record, allocation basis, and grant coding. If the employee worked on more than one award or function, show how the split was reviewed.

GrantPipe can help keep grant compliance evidence with the grant record, including deadlines, reports, restricted funds, and audit evidence. That matters when a sample touches both finance and program work.

## Prepare procurement files

Procurement is a common single audit risk. A purchase file should show how the vendor was selected, not just what was bought.

The file may include quotes, bids, sole source notes, conflict checks, contract approvals, and proof that the purchase matched the award budget. Follow the policy that applies to your organization and award. Federal awards may also require Uniform Guidance procurement support.

Do not wait for the sample to find these records. Procurement support is often held outside accounting, which makes it hard to reconstruct later.

## Prepare reporting support

Federal reports should tie back to the ledger, program records, and review notes. Save the report as submitted, not only the draft.

For each report, keep:

- Submitted copy
- Submission timestamp or confirmation
- Source schedule
- Ledger tie-out
- Reviewer approval
- Notes for estimates or corrections

If a report was revised, keep both versions and the reason. The auditor needs the path from source data to final submission.

## Prepare subrecipient support

If the nonprofit passed federal funds to another organization, the file should show how it monitored that subrecipient. Include the agreement, risk assessment, reports, invoices, monitoring notes, audit review, and follow-up.

Subrecipient monitoring is not the same as vendor invoice review. The file should show that the nonprofit checked performance and compliance, based on risk and award terms.

## Track follow-up until close

The PBC checklist should remain active through the whole audit. Add follow-up requests, owner names, due dates, and closure notes.

After the audit, save the final checklist with the audit report. If there are findings, link each finding to the evidence gap and corrective action plan. That makes next year's audit easier and helps management avoid repeat findings.

A good single audit PBC file is plain. It shows what was awarded, what was spent, what was reported, who reviewed it, and what evidence supports the answer.
