# Audit-ready grant expense sampling guide

Grant expense samples test whether a cost belongs on the grant. The auditor may start with the ledger, but the answer is in the evidence. A strong sample file shows what was bought, why it was charged to the grant, who approved it, when it was paid, and how it fits the award.

The best time to prepare is before the auditor selects samples. If each transaction has support during normal work, fieldwork becomes a retrieval task instead of a search.

## Start with the grant expense population

The population should include the full set of grant expenses for the period being tested. It should tie to the general ledger and grant budget report.

Before sending the population, check:

- Grant code
- Fund code
- Account code
- Transaction date
- Posting date
- Vendor or employee
- Amount
- Budget line
- Description
- Reversals or corrections

The total should tie to the grant expense report. If the report given to the funder differs from the ledger, explain why before the sample is selected.

## Build one sample folder per item

For each selected item, create one folder. Name it with the sample number, transaction date, vendor or employee, amount, and grant code.

Add an index to the folder. The index should list each support file and what it proves.

For a vendor expense, include:

- Invoice or receipt
- Purchase approval
- Payment proof
- Ledger detail
- Grant budget line
- Award period check
- Procurement support, if needed
- Notes for split coding

For payroll, include:

- Payroll register
- Pay rate support
- Time record or allocation support
- Approval
- Grant coding
- Fringe calculation, if charged

## Prove the cost fits the award period

Grant samples often fail because the date is unclear. The invoice date, service date, payment date, and posting date can differ. The auditor needs to know whether the cost fits the grant period and report period.

Add a note when dates differ. For example, a July payment may relate to June services. The invoice or contract should support that timing.

Do not rely on payment date alone. A cost may be paid during the grant period but relate to work outside the period. Ask your auditor how the award terms apply.

## Prove the cost was approved

Approval evidence should be dated and tied to the purchase. A typed name in a note is weaker than a workflow approval, signed invoice, or email approval that names the item.

The approver should have the right authority. If the policy requires executive approval above a threshold, include that approval. If a grant manager must approve grant costs, include that review.

For restricted funds, approval should also show that the cost fits the donor or grant purpose.

## Prove the cost was allowable and allocable

For federal awards, Uniform Guidance cost principles discuss allowability, reasonableness, and allocability. In plain terms, the file should show the cost was needed for the award, was reasonable for the work, and was charged based on benefit.

A shared cost needs an allocation basis. A payroll charge needs time or effort support. A supply purchase needs a link to the grant activity. A travel cost needs the purpose and approval.

GrantPipe can help teams keep grant compliance records, deadlines, restricted funds, audit evidence, donor CRM context, and reporting support tied to the award. That reduces the chance that finance and programs keep separate explanations for the same cost.

## Add procurement support when needed

Some samples need procurement evidence. The file may need quotes, bids, contract approval, sole source notes, conflict checks, or policy references.

Do not wait for the auditor to ask. If the transaction crosses an internal or federal threshold, add the procurement file to the sample folder. If no procurement was required, note why.

The goal is not to overdocument every small purchase. The goal is to show that the purchase followed the rule that applied.

## Tie samples to reports

If the expense was included in a reimbursement request, SF-425, funder report, or board report, link the sample to that report. Include the source schedule and submitted report when relevant.

This helps the auditor see the path from transaction to report. It also helps staff catch errors before they become questioned costs or report corrections.

## Track exceptions and lessons

Use a sample tracker during fieldwork. Track owner, files ready, reviewer, submission date, auditor follow-up, and closure.

After the audit, review every follow-up question. If samples often missed approvals, fix the purchase workflow. If payroll samples lacked support, fix time records. If costs were miscoded, fix the grant coding review.

Audit-ready grant expense sampling is not about making a pretty folder after the fact. It is about keeping support with each transaction as work happens. Then the sample file can answer the auditor's question with records, not memory.
