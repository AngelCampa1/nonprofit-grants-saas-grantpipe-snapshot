# Outcome verification file guide for nonprofits

Outcome numbers can carry a lot of weight. A grant report may use them to show progress, support renewal, explain spending, or close an award. The number should be easy to trace.

An outcome verification file keeps that support in one place. It does not need to be complex. It needs to answer a few plain questions: What did we count? Where did the data come from? How did we check it? What did we say in the report?

## Start with the exact outcome

Copy the outcome from the proposal, award agreement, or report form. Do not rewrite it yet.

Record:

- Outcome wording
- Report period
- Funder requirement
- Target if one exists
- Source system
- Program owner
- Grants owner
- Review deadline

This gives the team one shared definition. It also prevents a common mistake: reporting a similar number because it is easier to pull.

## Define the measure

Every outcome needs a plain definition. The definition should explain the numerator, denominator, date range, and exclusions.

Example:

"Percentage of participants who completed both pre and post surveys and improved by at least one point."

That definition is better than "participants improved." It tells staff who counts and what counts as improvement.

If the funder gives a definition, use it. If the funder does not, write one before pulling data.

## Pull source data

Use the system of record when possible. That may be a program database, survey tool, case management system, partner report, or approved spreadsheet.

Save the source or a controlled summary. Include the export date, filters, and report period. If the source contains private data, limit access and remove fields that do not support the outcome.

Do not build the outcome number from memory or email summaries. Those may help explain context, but they should not be the main source.

## Write the calculation

The calculation should be clear enough for another staff person to repeat.

Include:

- Data source
- Filters used
- Records included
- Records excluded
- Duplicate rule
- Formula
- Final number
- Reviewer

If the result is a rate, save the count behind the rate. A report that says 84 percent should also show 42 of 50, or whatever count applies.

## Review limits

Outcome data often has limits. A low survey response rate, missing follow up, late data entry, or small sample can affect how the result should be written.

Do not hide limits that matter. The report can still be useful when it is honest.

Plain language works:

"Of the 48 participants with both surveys, 36 improved their score."

That line is stronger than a broad claim about all participants. It tells the reader what the data covers.

## Approve the meaning

The program owner should approve what the number means. The grants manager should approve that the wording fits the funder question. Finance may need to review if the outcome connects to payment, match, units, or restricted fund release.

Save approval evidence. An email, task approval, or signed worksheet can work. The approval should include the outcome, final number, reviewer, and date.

## Save final wording

The final report wording belongs in the verification file. This helps the team compare the report to the source later.

Save:

- Final narrative sentence
- Final table value
- Submitted report
- Submission receipt
- Funder questions
- Corrections if any

GrantPipe can help teams connect outcome files to grant reports, due dates, restricted funds, and audit evidence. That makes it easier to answer a funder question after submission.

## Use the file for renewal

After the report is done, use the verification file to improve the next grant cycle.

Ask:

- Was the outcome easy to measure?
- Did staff collect the data on time?
- Did the measure match the program?
- Did the funder value the result?
- Should the next proposal use the same target?

Outcome verification is not just a compliance task. It protects the nonprofit from weak claims and helps staff choose better measures next time.

A good file is plain. It shows the source, the math, the review, and the final words. That is enough for most grant reporting work.
