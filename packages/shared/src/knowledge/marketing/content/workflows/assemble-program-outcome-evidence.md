Grant reports often fail in small ways. The story sounds right, but the number is hard to trace. The date range does not match the report. A program output is called an outcome. The source file sits in one person's downloads folder.

Outcome evidence fixes that. It gives each reported result a source, a date range, a calculation, and an owner.

This workflow helps program and grants teams prepare evidence before a report or renewal request. It is not a full evaluation plan. It is a practical way to keep reported results honest and easy to review.

## Step 1: list the promised measures

Start with the proposal, grant agreement, or report form. List every measure the funder expects.

Separate three types of information:

- Activities, such as workshops held
- Outputs, such as people served
- Outcomes, such as skills gained or jobs retained

Do not blur these. A count of people served is useful, but it is not the same as a result that changed for those people.

If the report asks for a measure your team does not collect, mark it right away. The answer may be to explain the gap, collect it now, or adjust the renewal plan. Do not create a number without support.

## Step 2: define the report period

Outcome evidence needs a date range. Use the report period from the funder. If the report covers April through June, the source data should cover that same period unless the instructions say otherwise.

Write the date range on the evidence worksheet. This prevents a common mistake: using year to date data in a quarterly report or current quarter data in a fiscal year report.

## Step 3: pull the source files

Collect the source files from the system that holds the data. That may be a case system, survey tool, attendance sheet, program database, partner report, or spreadsheet.

Save the source with a clear name. Include the program, measure, period, and export date.

Do not paste raw participant details into the grant file unless the funder requires it and your privacy rules allow it. In many cases, a summary file and calculation note are enough for the report packet.

## Step 4: write the calculation

Every number in the report should have a plain calculation note. Keep it simple.

Examples:

- "Count of unique participants with at least one completed workshop from April 1 to June 30."
- "Average pre and post survey change for participants with both surveys."
- "Number of households receiving rental support during the report period."

If you exclude records, say why. If you remove duplicates, say how. If the number is an estimate, label it as an estimate and explain the basis.

## Step 5: check the number against the program story

The grants manager and program owner should read the number next to the narrative. The text should not claim more than the data shows.

For example, if the data shows 80 people attended, do not write that 80 people improved their skills unless you have evidence of the skill change. If the survey response rate was low, explain the limit in plain language when needed.

This is where careful writing matters. A report can be positive without being inflated.

## Step 6: connect outcomes to grant compliance

Some funders connect outcome reporting to payment, renewal, or closeout. Federal awards may have performance reporting rules, and private funders may have their own forms.

Add the report deadline, measure owner, and evidence file to the grant record. GrantPipe can help keep program evidence near grant compliance tasks, reporting deadlines, restricted funds, and donor CRM context. That saves time when the same outcome data supports a renewal brief or board report later.

## Step 7: get approval

The program owner should approve the meaning of the data. The grants manager should approve that the number matches the funder question. Finance should review if the measure connects to spending, match, units billed, or restricted fund release.

Save the approval note. It can be an email, task approval, or signed worksheet. The approval should include the report name, measure, final number, reviewer, and date.

## Step 8: save the packet

The final packet should include the measure list, source files, calculation notes, approval, final report, and submission receipt.

Keep the packet with the grant report, not just with the program team. If an auditor, funder, or new staff member asks where a number came from, the answer should be easy to find.

Good outcome evidence is plain and traceable. It does not make the program look better than it is. It helps the team report what happened with proof.
