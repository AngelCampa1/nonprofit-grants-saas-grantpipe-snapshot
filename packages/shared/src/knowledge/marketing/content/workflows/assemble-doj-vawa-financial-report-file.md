A DOJ VAWA financial report should be easy to trace. Someone should be able to open the file and see how the numbers moved from the ledger to the report.

Do not wait until closeout to build that file. Build it each reporting period. The report file should include the award terms, SF-425 support, drawdowns, match support if the award requires match, and proof of submission.

This workflow pairs with [prepare an SF-425 quarterly report](/workflows/prepare-sf-425-quarterly-report), but it is written for Office on Violence Against Women awards and DOJ financial guidance.

## Step 1: read the award and conditions

Start with the award document. Confirm the award number, project period, budget period, approved budget, financial report due date, and reporting system.

Then review current OVW award conditions. Some conditions apply broadly. Others may be tied to the specific award.

Save the award terms used for the report. If the terms answer a question about match, budget limits, or special costs, keep the relevant page in the packet.

## Step 2: pull the prior report

The current report should continue from the prior accepted report. Pull the last SF-425 or agency report and compare beginning amounts.

If the prior report was corrected, use the accepted corrected version. Keep both versions and the reason for the correction.

This step prevents quiet drift. A small difference can grow each quarter if no one checks it.

## Step 3: reconcile expenditures

Pull ledger detail for the report period and inception-to-date spending. Tie the report's federal share of expenditures to the ledger.

Review large or unusual costs. Check that costs are inside the project period and fit the approved budget. If a cost needs prior approval, keep that approval with the line.

VAWA-funded work can include sensitive program activity. Do not save private client details in the financial report file. Use financial support that proves the cost without exposing protected information.

## Step 4: reconcile cash and drawdowns

Compare federal cash received to drawdown records and bank deposits. The cash lines should agree with the payment system record and the bank.

If cash was requested but not received by period end, note the timing. If cash remains on hand, explain why and whether the next draw should be reduced.

The [federal drawdown workflow](/workflows/review-federal-drawdown-before-request) can be used before each request so the report file is easier to assemble.

## Step 5: check match and obligations

If the award requires match, build a match schedule. Tie each match item to source support, period, funding source, and eligible activity.

If the SF-425 includes unliquidated obligations, list them. Each obligation should have support, such as a contract, purchase order, or approved payroll commitment.

Do not use obligations to show planned spending that has no real commitment. The file should support the amount reported.

## Step 6: review the report line by line

Before submission, compare each report line to the support worksheet. Use a second reviewer when possible.

Check award number, report period, cash received, cash disbursed, federal expenditures, recipient share, program income, obligations, remarks, and the certifying official.

The reviewer should write short notes for any timing difference, correction, or unusual line.

## Step 7: save submission proof

After submission, save the final report, support worksheet, ledger detail, drawdown records, cash support, match support, reviewer approval, attachments, and submission confirmation.

Use a folder name that includes the award, report period, and submission date. This helps during audit and closeout.

## Common file gaps

The most common gap is a report saved without the worksheet behind it. The second gap is cash support that does not tie to the bank. The third is match support that proves a cost existed but not that it was eligible match.

Fix these gaps during the reporting cycle. Do not leave them for year-end.

## Protect sensitive support

VAWA award files can touch services for people in unsafe situations. The financial report file should prove costs without spreading private details.

Use payroll totals, coded invoices, contracts, and summary records when they are enough. If a record includes names, addresses, case notes, or other sensitive facts, store it in the right restricted location and link to it only if the team is allowed to do so.

Tell reviewers where sensitive proof lives, but do not copy it into broad finance folders unless policy allows that. A clean report file should support the numbers and protect people at the same time.

If a redaction is used, save the unredacted source in the approved secure place. Note who can access it.
