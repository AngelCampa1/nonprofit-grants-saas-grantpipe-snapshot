A board schedule for restriction releases should help leaders govern. It should not force them to read the whole ledger. It should show what was released, why it was released, what remains restricted, and what still needs attention.

This workflow helps finance prepare the schedule for a board or finance committee packet. It is not accounting advice. Follow your policy for approvals and final treatment.

## Step 1: choose what needs board visibility

Start with the restricted fund rollforward. Pick funds that are material, risky, close to a deadline, tied to a board commitment, or important to cash planning.

Do not fill the schedule with tiny rows that hide the real story. Small funds can stay in a detail appendix if needed.

GrantPipe can help connect restricted funds, reporting deadlines, donor CRM context, and audit evidence. The board schedule should turn that detail into a clear review page.

## Step 2: show the release amount and basis

For each row, show the release amount and the basis. Use plain language.

Examples:

- Eligible program costs incurred in June
- Time restriction ended on June 30
- Capital project milestone met
- Donor report approved
- Partial release based on payroll support

Avoid notes such as "per GL" or "per finance." Those notes do not tell the board why the release is valid.

## Step 3: show the remaining balance

A release schedule without remaining balances is incomplete. Leaders need to know what is still restricted.

Include the beginning restricted balance, new restricted activity, release this period, and ending restricted balance. If space is tight, show current period release and ending balance, then keep the full rollforward in the finance file.

Add a note when cash and restricted balance differ. For example, a pledge receivable may be restricted but not collected. An advance may be cash on hand but still restricted.

## Step 4: add evidence status

Each material release should have an evidence status. Use simple labels:

- Complete
- Pending reviewer approval
- Missing support
- Needs donor or funder clarification

Do not send a schedule with "complete" unless the support exists. Evidence can include the agreement, expense detail, payroll allocation, program record, date support, approval, and journal entry.

## Step 5: add deadlines and risks

Restricted fund releases often connect to reports and deadlines. Add report due dates, spend-by dates, closeout dates, or board decision dates when they matter.

Use a risk note for items that need action. Examples include missing support, late report, negative balance, old receivable, fund closeout risk, or cash pressure.

The note should name the owner and next action. "Finance will request June payroll support by July 8" is useful. "Review needed" is not enough.

## Step 6: review before the packet

Finance should review the schedule with the executive director or finance lead before the board packet is final. This catches unclear labels, missing evidence, and operating cash issues.

The reviewer should be able to answer:

- Did we release only supported amounts?
- Do remaining restrictions make sense?
- Are deadlines visible?
- Are risks assigned?
- Does the schedule match the rollforward?

## Step 7: save the final packet

Save the board packet version with the support file. If the board asks questions or approves an action, save the minutes or follow-up note.

This matters for audit evidence. The board schedule shows oversight. The finance file proves the entries.

## Keep the schedule stable

Use the same columns each time. Board members can review faster when the layout does not change every month.

If a fund drops from the schedule, note why. It may be fully released, immaterial, closed, or moved to an appendix. If a new fund appears, add one plain sentence that explains the restriction and release trigger.

Stable reporting also helps finance. The team can compare last month to this month without rebuilding the format. That makes unusual changes easier to spot before the packet is sent.

## Outputs

The finished workflow produces a board-ready schedule, evidence status summary, risk notes, deadline view, and reviewer approval.

## Common failures

Common failures include showing releases without evidence status, hiding remaining balances, using fund codes no one explains, and leaving out deadlines.

Another failure is mixing board oversight with accounting support. The board schedule should not be the only proof. It should point to the proof.

## What to save

Save three layers of support. First, save the board-facing schedule that shows what changed and what remains restricted. Second, save the accounting support that proves each release. Third, save any board minutes, finance committee notes, or follow-up answers tied to the schedule.

This separation matters. Board members need a clear view. Finance and auditors need proof. Keeping both together helps the next monthly close start from a clean record.

## Automation ideas

Automation can draft the schedule from release entries, pull deadlines from grant records, flag missing support, and show which restricted funds changed since the last packet.

Automation should make the board packet easier to prepare. It should not label a release as supported unless the evidence exists and a reviewer has checked it.
