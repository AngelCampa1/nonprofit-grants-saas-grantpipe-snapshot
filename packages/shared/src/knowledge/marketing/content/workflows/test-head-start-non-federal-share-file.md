Head Start non-federal share support needs a real test before it is reported. A pledge, plan, or rough estimate is not enough.

The file should show where the support came from, how it was valued, when it was provided, and how it helped the Head Start program. That applies to cash and in-kind support.

Use this workflow before quarterly review, annual reporting, or closeout. It works well with a broader [grant documentation checklist](/resources/guides/grant-documentation-checklist-audit-ready).

## Step 1: confirm the target

Start with the award and budget. Confirm the non-federal share amount or percentage required for the period being tested.

Then compare that target to match already accepted in prior periods. The current test should show what is new and what has already been counted.

If the organization has an approved waiver or reduced requirement, keep the approval in the file. Do not assume a waiver applies without source support.

## Step 2: build one support list

Create one list for all proposed non-federal share items. Include cash and in-kind support.

For each item, list source, date, amount, type, program activity, support file, and whether it has been counted before.

Cash items may tie to payroll, invoices, or other ledger records. In-kind items may include donated time, space, goods, or services if allowed and supported.

## Step 3: test the period

Each item should fall inside the award or budget period being reported. Check service dates, donation dates, payroll dates, invoice dates, and use dates.

If an item covers more than one period, allocate it. Keep the basis for the split.

Remove items outside the period unless the award instructions clearly allow them. A future reviewer should not have to guess why the date fit.

## Step 4: test program fit

The item should support Head Start activity. A donation to the organization is not automatically non-federal share for Head Start.

For volunteer time, check the activity description. For donated space, check how the space was used. For goods, check whether they were used by the program.

If the support benefits more than one program, count only the Head Start share.

## Step 5: test value

Cash value should tie to actual paid or incurred cost. In-kind value should be fair and supported.

For volunteer services, keep hours, work description, rate used, and approval. For donated goods, keep a receipt, donor note, or other value support. For space, keep the method used to support fair rental value.

Do not round up to meet the target. If a value is uncertain, use a supportable amount or exclude it.

## Step 6: check source and double counting

The same support cannot be counted twice. Compare the item to prior reports, other grants, and internal match schedules.

Also check whether the source is federal. Federal funds usually cannot be used as non-federal share unless a law allows it.

Keep notes for any item removed. This helps train staff and avoids the same issue next period.

## Step 7: reconcile to the report

Total accepted items. Compare that total to the amount planned for the report.

If accepted support is below target, tell leadership early. The answer may be more support, better documentation, or a waiver discussion with the grant office if allowed.

Save the test worksheet, source records, rejected item list, report tieout, and reviewer approval.

## Keep the file useful

A good non-federal share file can be read by someone outside the program. It explains each item without needing a meeting.

Before closeout, compare all tested periods to the final reported amount. Make sure no item appears twice and every reported dollar has support.

## Use the test to improve collection

The test should also show where support breaks down. If volunteer forms are late, fix the collection date. If donated goods lack value support, update the donor form. If program staff cannot explain how space was used, add a simple use log.

Track these issues in the worksheet. Do not treat them only as one-time fixes.

Non-federal share is easier to support when records are collected at the time of service or donation. Rebuilding the file months later is slower and less reliable.

Share a short issue list with program managers after each test. Keep the tone practical. The goal is a cleaner next file.

Update the form before the next service period starts.

Then test the new form with one real record.
