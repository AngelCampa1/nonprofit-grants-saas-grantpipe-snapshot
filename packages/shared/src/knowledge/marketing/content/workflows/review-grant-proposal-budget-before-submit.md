A grant proposal budget is more than a table. It is a promise about how the organization will use the money. If the budget is rushed, the team may win a grant that is hard to manage.

This workflow helps a grants manager and finance reviewer check the budget before submission. It is meant for practical review, not legal or accounting advice. For federal awards, use the award rules and cost principles. For private grants, use the funder instructions and your finance policies.

## Step 1: freeze the draft for review

Set a review version before the deadline. Do not review a moving target. The grants manager should send finance the budget, budget narrative, funder instructions, work plan, and deadline.

Name the file with a date and version. If the team uses a portal, export or screenshot the budget page before review. Portal totals can differ from spreadsheets when fields are edited late.

## Step 2: check the funder rules

Read the funder instructions next to the budget. Check whether the grant allows salary, fringe, equipment, travel, food, incentives, indirect costs, rent, subawards, and match.

Federal grant budgets should also be checked against basic allowability rules. Section 2 CFR 200.403 describes general factors for allowable costs. Section 2 CFR 200.414 covers indirect costs. The funder may add stricter rules.

If a cost is not allowed, remove it or move it to another funding source before submission.

## Step 3: match costs to the work plan

Every budget line should support the program story. If the proposal says the team will run 12 workshops, the budget should include the staff, materials, space, travel, or partner costs needed for that work.

Also check the reverse. If the budget includes a contractor, the narrative should explain what the contractor will do. If the budget includes software, the narrative should connect it to the funded work.

This is a common place to catch weak proposals. The budget and narrative should tell the same story.

## Step 4: test the math

Check every total. Recalculate salary percentages, fringe, unit costs, match, indirect costs, and the grand total. Confirm that the spreadsheet total matches the portal total.

Look for round numbers that need support. A rounded budget is not always wrong, but the reviewer should know the basis. "Supplies: $5,000" is weaker than "200 kits at $25 each."

## Step 5: review match and cost share

If the proposal includes match, finance should verify the source. Match can create real compliance work after award.

List each match source, amount, owner, and support. If match is in-kind, write down how it will be valued and documented. Do not count the same match for two grants unless the rules clearly allow it.

If match is uncertain, leadership should know before submission.

## Step 6: check restricted fund setup

If awarded, the grant may need its own code, fund, class, project, or tracking field. Finance should decide how costs, restricted funds, deadlines, reports, and audit evidence will be tracked.

GrantPipe can help connect donor CRM context, grant compliance tasks, restricted funds, budget notes, and reporting deadlines. That connection is useful because the proposal budget becomes the starting point for budget to actual review after award.

## Step 7: review the budget narrative

The budget narrative should explain the cost basis. It should not repeat the table in full. It should answer why the cost is needed, how the amount was calculated, and how it relates to the grant work.

Keep the wording plain. Avoid broad claims. If the source is a quote, salary schedule, vendor estimate, or approved rate, name it in the notes.

## Step 8: approve before submission

The reviewer should record approval before the proposal is submitted. The note should name the budget version, total request, match amount, key risks, reviewer, and date.

If leadership approves a known risk, such as unrecovered indirect costs or a tight match plan, save that decision. The award file should show that the risk was known before the grant was accepted.

## Step 9: save the final packet

After submission, save the final budget, budget narrative, portal receipt, reviewer notes, and approval record. If the grant is awarded, use this packet to set up the grant file.

A good budget review does not slow the proposal down for show. It catches problems while the team still has time to fix them.
