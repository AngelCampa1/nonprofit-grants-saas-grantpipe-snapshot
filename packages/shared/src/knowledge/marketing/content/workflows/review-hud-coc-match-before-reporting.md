HUD Continuum of Care match can look simple until report time. A grant budget may show the match plan, but the report needs proof of what actually happened.

The review should happen before the report is submitted. That gives the team time to remove weak items, find missing support, or explain timing differences.

This workflow focuses on the match file. Pair it with the broader [grant documentation checklist](/resources/guides/grant-documentation-checklist-audit-ready) when you build the full report packet.

## Step 1: confirm the match requirement

Start with the award and HUD CoC rules. Confirm the match percentage, project period, eligible activities, and whether the award has any special conditions.

HUD's CoC rule at 24 CFR 578.73 covers match. Federal cost sharing rules in 2 CFR 200.306 also matter. Use both when reviewing source support.

Write down the match target in dollars. Then compare it to match already reported. This prevents double counting and helps the reviewer see what remains.

## Step 2: separate cash and in-kind match

Cash match and in-kind match need different support.

Cash match usually ties to the ledger, bank records, payroll, invoices, or other paid costs. In-kind match may include donated goods or services if the rules allow them and the value is supported.

Create separate tabs or sections for each type. Do not mix them in one vague list. A future reviewer should know what was paid in cash and what was donated.

## Step 3: check the funding source

Match should not be paid with another federal source unless a law or award term allows it. That is a common risk.

For each cash match item, note the funding source. If it came from unrestricted funds, local government funds, private grants, or donations, name that source.

For in-kind match, name the donor or partner. Keep a letter, agreement, or other record that shows what was provided and when.

## Step 4: check the period and activity

The match should support the CoC project during the right period. Check the service date, payroll period, invoice date, or donation date.

Then connect the item to an eligible CoC activity. If an item supports a different program, remove it. If only part of the cost supports the CoC project, allocate only that part.

For shared staff or shared rent, keep the allocation method. A simple percentage is not enough unless the file explains why that percentage is right.

## Step 5: test the value

Cash match should tie to the amount paid or incurred. In-kind match needs a fair value. The value should be reasonable and backed by source records.

For donated services, keep time records and the rate used. For donated space or goods, keep a basis for the value, such as an agreement, invoice, or market support.

Do not inflate value to meet the target. If the file is short, report the shortfall and fix the process for the next period.

## Step 6: look for double counting

Match can be counted once. Review prior reports, partner reports, and internal schedules. Make sure the same invoice, payroll period, or donated service is not used twice.

Double counting can happen when finance and program staff keep separate spreadsheets. Use one final match schedule for the report.

The schedule should show item, date, amount, source, support file, eligible activity, and reviewer notes.

## Step 7: approve before reporting

Before submission, grants staff should review the program fit. Finance should review the source records and ledger tieout.

Save the approval with the report. If a match item was removed, keep a note about why. That note helps the next review.

## What to do when support is missing

Do not report a match item just because it was planned. If support is missing, set the item aside until the team can prove it.

If the amount is needed to meet the match target, tell the project lead early. The answer may be more source support, a different eligible match item, or a management decision about the report.

## Keep a match aging list

Create a match aging list before each report. Group items into ready, missing support, needs program review, and rejected.

This makes the review easier to manage. Finance can chase missing receipts or ledger records. Program staff can confirm whether donated services or partner support fit the CoC project. Leadership can see whether the project is at risk of falling short.

Do not delete rejected items from the working file. Keep them in a separate section with the reason. That record helps explain why the final reported match is lower than the first draft.

The aging list should also show items held for a later period. A valid match item can still be wrong for the current report if the date does not fit.

For closeout, compare the final match file to all reports filed during the project. The [close federal award file workflow](/workflows/close-federal-award-file) can help with that last review.
