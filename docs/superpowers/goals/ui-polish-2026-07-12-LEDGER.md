## Durable lessons

- **W2 reviewed edge case (accepted):** "Save current filters" now renders only with visible donor-list chrome; a canEdit org with saved segments but zero visible donors loses the button — nothing to save in that state, by design.

- **Coverage gate race even single-command:** `turbo test:coverage` for ui+web in ONE turbo invocation still races (`ENOENT coverage/.tmp/coverage-0.json`) because turbo parallelizes packages. Always pass `--concurrency=1`.
- **Cursor rule shape (reviewed):** soft-disabled (`aria-disabled="true"`) must be excluded from the pointer rule on `button` and `a[href]` too, not just `[role="button"]` (specificity beats the not-allowed rule otherwise). `label[for]` is deliberately NOT in the pointer rule — CSS can't see the referenced control's disabled state.
- **Buttons' cursor:default comes from the browser UA stylesheet**, not Tailwind v4 preflight — don't misattribute in comments.
- **Drizzle relational-API cross-table pitfall (AFF-16):** never pass raw `sql` fragments referencing OTHER tables' columns into the `where` of `db.query.*.findMany/findFirst` — the relational compiler re-qualifies every bare Column with the base table's alias (→ `donations.entity_id` 500s). Use the core `db.select().from().where()` builder for such predicates. Fully-mocked db tests cannot catch this class; anomaly.service has a source-contract guard.
- **Portal endpoints return RAW table rows by design** (grants/funds/programs alike). Web portal pages must read real column names (`type`, not `fundType`). Do NOT reuse authenticated services like getFund() there — they'd leak grant/expense data outside the reviewer's explicit scope grants.
- **external-reviewers list endpoints return `{items,total}`** — client unwrappers must handle that shape (settings.portal-access extractList bug).
