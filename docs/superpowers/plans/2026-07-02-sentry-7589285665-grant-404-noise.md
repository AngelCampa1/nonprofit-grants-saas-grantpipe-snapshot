**Goal:** Stop expected grant soft-delete 404 checks from opening Sentry issue `GRANTPIPE-API-1R` while preserving Sentry capture for real entity-scoped grant access denials.

**Architecture:** Keep the fix at the API error boundary. `AppError(404, "Grant not found")` from grant routes should remain a normal HTTP response and should not be sent to Sentry; `AppError(403, ...)` on entity-scoped grant routes should still be captured with the existing sanitized message and scope tags.

**Tech Stack:** Hono API middleware, Vitest, `sentry-cli`, Wrangler deploy scripts.

```ts
function shouldCaptureEntityScopedAppError(err: AppError, c: Parameters<ErrorHandler>[1]): boolean {
  if (err.status !== 403) return false;
  const entityId = getOptionalContextValue<string | null>(c, "entityId");
  if (!entityId) return false;
  const routePath = c.req.routePath || c.req.path;
  return isGrantsRoutePath(routePath) || isGrantsRoutePath(c.req.path);
}
```
